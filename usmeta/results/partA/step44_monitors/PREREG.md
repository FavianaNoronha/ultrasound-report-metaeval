# Step 44 pre-registration: scorers as monitors (written 2026-11-18, before any Step 44 test number)

Question: if each scorer is used as an audit monitor that flags the lowest-scoring share of reports, how many planted errors does it catch, at what cost in flagged correct / harmless reports?
Rules: only scores already on disk, **no new model call**; the locked 40/20/40 group split; every threshold chosen on **val only**; report on **test**; group bootstrap (group = `dataset:group_id`), 1,000 resamples, seed 0; any cell with fewer than 30 groups is marked †.
Honest note: the per-pair test scores for BLEU, ROUGE-L, chrF, BERTScore, RaTEScore, finding_f1 and the judge have been used in earlier steps (AUROC, Steps 5-30). No catch-rate, flagged-share, cascade or reason-match number has been computed. Before this file I only counted how many saved rows exist per scorer and split (coverage below).

## Data (saved files only)
- Candidates: `bench_val_v2d.jsonl` (val) and `bench_test_v2d.jsonl` (test), via `step19_pairs.load`. Pool = every planted error, every harmless rewording (small, matched, large, other) and every identical copy ("correct"). The benchmark prevalence of errors is not a real-world rate; **catch rate does not depend on prevalence, flagged-share-of-correct does not either, but precision would, so no precision or PPV is reported.**
- Scores: `scores_{val,test}_layer0.json` (BLEU, ROUGE-L, chrF, BERTScore roberta-large, RaTEScore), `scores_{val,test}_layer1.json` (finding_f1), judge replies for the judge subset (test: `judge_test_v2.jsonl` + `judge_big_v2.jsonl`, 2,568 pairs; val: dev-era sample, 186 pairs in the val split, 1,104 judged rows). Score direction: lower = flag.
- Coverage found before writing this file: the text scorers cover 100% of val (16,200) and test (25,887) rows. The judge covers 2,568 test pairs and only 186 val pairs (pooled over datasets, so every judge val cell is small and labelled). `llm_finding_f1` exists for the same 2,568 test pairs but for **no** val pair; RadGraph-F1 exists for 13,058 test pairs and about 2,600 val pairs (Steps 33-35 designs, not a random sample of the benchmark); the U-Net image check exists for 119 test scans and no val scan.

## Operating point and thresholds (val only)
- Nominal budget X in {1, 2, 5, 10}%. For each scorer, threshold t_X = the X-th percentile of that scorer's scores over the **val pool** (all kinds). A test candidate is flagged iff score <= t_X. Because many scorers tie (finding_f1, judge), the **realised** flagged share on test is reported next to the nominal budget; the realised share is the number to read.
- Judge: t_X from the 186 val judge pairs; test pool = the 2,568 judged test pairs. To compare like with like, every scorer is also reported on **the same judge subset** (thresholds still from the val pool of that scorer on all val rows).
- llm_finding_f1: no val scores, so **not available** as a budgeted monitor (reported as such, no threshold taken from test). RadGraph-F1: reported only on the test rows that have a saved score, threshold from the val rows that have a saved score, marked "partial coverage, subset not random, not comparable with other rows" (needs val >= 1,000 rows and >= 30 val groups, else "not available"). U-Net image check: no val scores, so no budget; reported at its **fixed Step 20 rule** (tau and position tolerance chosen on dev/val in Step 20, saved in `step20_tolerance_image_check/tuning_devval.json`), on the 119 test scans, mask-checkable error fields only, flagged = Step 20 score below 1, with the realised flag share on the same scans' harmless/identical candidates; labelled "fixed operating point, not a budget".
- Ceilings, reported in a separate table and labelled "upper bound on templated text, not a deployable monitor": finding_f1 and the MedSAM true-box check (the oracle-box image check of Step 16 / Step 30 is used if saved; if the saved masks do not give a per-candidate score for test, it is stated "not available").

## Analyses
A. **Catch rate** = planted errors flagged / planted errors, per scorer and budget (nominal and realised), pooled and per organ (breast / thyroid / fetal head). Group bootstrap CIs.
B. **Severity-weighted catch rate** = sum of severity (1 minor, 2 major, 3 critical, as stored in the benchmark) over flagged errors / sum over all errors, plus catch rate per severity level. The severity levels are **our own provisional labels, not clinician-set** (Step 30 shows them confounded with error type and edit size). The write-up cites that severity-based monitoring is prior art (DrugBench, arXiv 2606.20663; to be verified, see checks) so no novelty is claimed.
C. **Safety vs usefulness**: for each budget, share of errors caught vs share flagged among (i) harmless rewordings (small / matched / large / other, and pooled) and (ii) identical copies ("correct"). The same bootstrap.
D. **Cascade** (judge-subset test pairs only): stage 1 = a cheap scorer (BLEU, ROUGE-L or chrF) flags the lowest s% by its val threshold, s in {10, 20, 40}%; stage 2 = the judge scores **only** the flagged candidates and flags those at or below its val threshold for budget b in {5, 10}%. Final flag = both. Report cascade catch rate and false-flag shares vs the judge alone at the same b, and judge calls saved = 1 - (share of pool sent to the judge). No new judge call is made (replies for all judged pairs exist; saved calls are counted as calls that would be avoided).
E. **Judge reason-match** (judge test subset, planted-error pairs the judge flagged at all, i.e. at least one listed error): the judge's listed error text is recovered from the saved raw replies in `.llm_cache` (read-only lookup; the cache key reproduces the Step 7 prompt; all 2,568 pairs are present). Two measures: (1) **category match** = a listed error has the same `category` as the planted error's category; (2) **field match** = a listed error's free-text `field` contains a keyword of the planted field (frozen keyword map in the script: e.g. size_pct/size_mm: size, measur, mm, cm, width, %; hc_mm: head, circumference, hc; lesion: mass, lesion, nodule, finding; orient: orient, wider, taller, shape; count: count, number, foci, nodule; pos: locat, position, quadrant, central, upper, lower; side: side, left, right; birads: bi-rads, birads, assessment; tirads: ti-rads, tirads; path: patholog, malignan, benign; hist: histolog; margin; plane; echo; shape; calc; halo; foci; comp: composition, solid, cystic; post: posterior). The keyword rule is a proxy, not a human read; the share is reported with its group-bootstrap CI, per planted field, and the share among **all** planted errors (counting un-flagged ones as no match) is reported too.
F. **Step 39b (exploratory, labelled so; does not change the Step 39 H1 result, 39.2% vs 21.5%, not supported)**. Using the saved Step 39 replies (set A = P0, P1, P2; set B = P3, P4, P5; ensemble = mean `judge_score`) on the pairs that have all six replies: flag threshold chosen on val from the P0 val judge pool at budgets 5% and 10% (val has no planted-error replies for P1-P5, so the P0 val threshold on the shared judge_score scale is used for every prompt and ensemble; stated as a limitation). On test: agreement rate of flag decisions between (i) ensemble A vs ensemble B and (ii) P0 vs P3 (single prompts), each with a group-bootstrap CI, overall and for planted errors only / harmless only, plus the share of errors each flags. No hypothesis test and no verdict is attached.

## Not done / limits stated in advance
One model family for the judge; templated text only (no HiSBreast, no free text); the pool prevalence is the benchmark's; the judge test subset is a stratified sample (59 cases per dataset, Steps 10d + 12) and its val sample is small; RadGraph-F1 is partial; the U-Net check covers only mask-checkable fields on 119 scans; severity is not clinician-set; the reason-match is a keyword proxy.
