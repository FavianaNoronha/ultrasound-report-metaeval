# Step 11 re-run 2: Qwen real reports with BrEaST added and extractor v2

**Possible training exposure, unverifiable.** BrEaST is a public archive; Qwen2.5-VL-3B may have seen it (and BUS-BRA, TN3K, TN5000, HC18); its model card lists no training data. Limitations: [docs/LIMITATIONS.md](../../../docs/LIMITATIONS.md). The original Step 11 folder (`step11_qwen_real_reports`) is kept; this re-run changes two things: (1) the free-text extractor is **v2** (`schema_v2.py`, see `step11b_extractor_v2`), (2) **BrEaST is added**: 50 scans plus 5 mirrored copies, same Qwen2.5-VL-3B prompt and settings (`usmeta/generate_brest.py`). BrEaST split: 19 test reports (final numbers), 31 dev/val (checks); the 5 mirrored BrEaST copies fall in dev/val, so the flip test (10 test scans) is unchanged. Everything else (Gemma-2-9B extractor and judge, prompt_v1 and prompt_v2, boxes, scoring) is as in Step 11. Test reports: BUS-BRA 21, **BrEaST 19**, HC18 14, TN3K 22, TN5000 16 (n small: read intervals, not rankings).

**Extractor check on BrEaST (dev/val, before the test numbers):** proxy agreement with independent regex readings **37 of 37 = 100% on 10 reports** (side 9/9, BI-RADS 10/10, size 9/9, lesion 9/9) -- still a regex proxy on 10 reports, not a labelled test. Box parsing check: the 5 dev BrEaST scans parsed 5/5; all 132 box outputs in this run parsed.

**BrEaST results (test, n = 19; 19 groups).**
- **Layer 1:** `finding_f1` 0.18 (95% CI 0.14-0.21); precision 0.23, recall 0.14. BrEaST's true report states up to 13 attributes (lesion, shape, margin, echo, posterior features, calcifications, halo, size in mm, image position, orientation, BI-RADS, pathology), so low recall is partly "not stated". Per attribute (19 reports): BI-RADS stated in all 19, **exact match 0/19; ignoring the a/b/c suffix 4/19 (21%)** (reference BI-RADS in this sample: 3 x8, 5 x4, 4c x3, 4b x2, 4a x2; in the pairs I looked at Qwen said 2 or 4); size in mm: correct (within the 50% credit band) 3, wrong 14, not stated 2 (note: BrEaST size is approximate: pixel-size unit inferred); shape correct 1, wrong 15, not stated 3; margin wrong 12, not stated 7 (wording mismatch counts as wrong: "indistinct" vs "not circumscribed (indistinct)"); echo correct 8, wrong 5, not stated 6; posterior features wrong 5, not stated 14; calcifications correct 3, not stated 16; halo not stated 19; pathology correct 3, not stated 16.
- **Layer 2 (Gemma `sentence_check`):** `sentence_f1` 0.37 (0.29-0.44) with prompt_v2, 0.57 (0.51-0.63) with prompt_v1 (the prompts differ by 0.2 again); the judge lists at least one error in 100% of reports; error types named (prompt_v2, counts): false finding 43, wrong severity/category 20, wrong location 19, wrong measurement 18, missed finding 14.
- **Layer 3 (Qwen boxes vs the true lesion box/mask):** mean best-match IoU **0.24 (0.14-0.34)**, 24% of scans with IoU >= 0.5; pixel recall 0.96 but pixel precision 0.19 (large boxes); share of boxes with >= 50% inside the true box region 0.24.
- **Do text scores follow location quality?** Spearman text score vs IoU on BrEaST (n = 19): BLEU -0.12, chrF +0.20, `finding_f1` +0.26, `sentence_f1` v2 +0.29: weakly positive, but n is 19 and none of it is distinguishable from zero here.

**The four other datasets with extractor v2 (test).** Unchanged in practice: `finding_f1` BUS-BRA 0.24, TN3K 0.23, TN5000 0.20, HC18 0.00; `sentence_f1` v2 / v1 BUS-BRA 0.27 / 0.57, TN3K 0.18 / 0.47, TN5000 0.22 / 0.50, HC18 0.80 / 0.77; box IoU BUS-BRA 0.21 (10% of scans >= 0.5), TN3K 0.30 (23%), TN5000 0.12 (0%), HC18 0.77 (93%). Changes from v1: the lesion field now has one "wrong" (absent) in each of TN3K and TN5000 (the boolean-lesion fix), and BUS-BRA BI-RADS exact match 6/21 stays (ignoring suffix 9/21; one extracted value was the fragment "bi-r", an extraction slip). Per-attribute tables for these datasets as in Step 11.

**Where BrEaST sits.** BrEaST is the "cleanest" check only by guess (newest, smallest public set). Qwen does no better there than elsewhere on location (IoU 0.24 vs BUS-BRA 0.21, TN3K 0.30) and BI-RADS (exact 0/19 vs BUS-BRA 6/21), and its richer expert descriptors show the model rarely matches shape and margin (1 and 0 correct of 19). This neither supports nor rules out exposure.

**Caveats.** Templated true reports (not clinician text) against free text, so vocabulary and detail mismatches inflate "not stated"/"wrong"; BrEaST size is approximate; n = 14-22 per dataset; the extractor proxy is regex-based on 10-40 reports per set; the judge is prompt-sensitive (two prompts shown); results are per dataset; MedGemma and LLaVA-Med not run.
