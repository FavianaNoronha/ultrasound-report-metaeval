# Step 47 preregistration amendment (before Set C data generation)

This amendment clarifies operational details that were underspecified in `PREREG.md`. It was written before reading or generating any Set C test case or recording any Step 47 score. The original hypotheses and fixed variants remain unchanged.

1. **Exact writer.** Set C uses `mlx-community/Mistral-7B-Instruct-v0.3-4bit`; the resolved Hugging Face revision and model-file hash will be recorded before generation. The fixed report prompt and decoding settings will be hashed in `run_info.json`.
2. **Meaning of fresh cases.** Set C test case IDs are excluded from the prior AI-writer and human-rewording report sets: Step 11/14 report generations, Steps 28/32/43 Qwen-VL reports, Step 21d human rewordings, Step 45 Set A, and Step 46 Set B. Set C is not claimed to use images never touched by any earlier templated benchmark or image-check experiment.
3. **Set R labels.** The 30 existing human answers in Step 43 are one reviewer's labels of whether extractor v4 faithfully copied facts stated in Qwen-VL report text. They do not label whether the report is correct against the scan. Set R is therefore a descriptive comparison to extraction-faithfulness labels only and cannot validate report correctness or clinical usefulness.
4. **Quote prompts and disagreements.** The three fixed audit prompts are stored in `prompts.json`: reference-first Prompt A, candidate-first Prompt A with the same report roles, and the reworded Prompt B. Order and prompt disagreements compare verdict plus sorted issue-type/severity pairs; quote wording differences alone do not count as disagreement. Every candidate quote must be an exact substring of the candidate report; every non-empty reference quote must be an exact substring of the reference.
5. **Common routing budget for H2.** The V3 route share on saved Set B dev/val is the fixed routing budget. CRQS, BLEU, ROUGE-L, chrF, BERTScore, RaTEScore, and Step 45 learned scores are calibrated on the same Set B dev/val reports to that route count. If a scalar cutoff ties, ties are resolved by a stable SHA-256 of the report ID. Cutoffs and tie rules are frozen in `thresholds.json` with its SHA-256 before Set C is planned. H2 requires V3 to beat CRQS and each text metric; the Step 45 learned comparison is reported as a secondary result. Test labels never set a cutoff.
6. **Uncertainty routing.** Invalid JSON, any invalid required quote, disagreement between the two fixed prompt presentations, or disagreement between the rule checker and the audit judge counts as `unsure` for V3. V4 removes only these uncertainty routes; it still routes rule-major cases and valid-quote judge-major cases.
7. **H1 denominator and confidence interval.** “Share of reports auto-passed that contain a major or critical planted error” means the number of un-routed major/critical error reports divided by all un-routed core reports. The 95% interval resamples report groups (1,000 draws, seed 0); the harmless-route limit is reported as its point share.
8. **H7 reference set.** The available Step 46 comparison set is Set B, a held-out writer-generated report set. The preregistration’s phrase “templated test” is corrected to “Step 46 Set B writer-generated test”; H7 is descriptive and no templated-test comparison is claimed.

No Step 47 test result is available at the time of this amendment.
