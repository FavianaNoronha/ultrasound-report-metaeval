# Step 47 preregistration amendment 2 (before freeze-devval and before any Set C generation)

Written 2026-11-23. No Set C case has been generated and no Step 47 test score exists. Only dev/val judge calls exist; the audit judge prompts, `prompts.json` and Amendment 1 are unchanged except where stated below. Where this amendment and Amendment 1 conflict, this amendment governs.

1. **Severity leak fix.** `severity_for` in Step 46 reads the planted severity when a case has one, and Step 47 passes `case["twin_severity"]` into it. From now on every scorer variant takes severity only from `extract.WEIGHTS` (weight >= 3 critical, 2 major, else minor). The planted label is used only to define outcomes. A unit test must show scores are identical when the planted severity and kind fields are altered. The Step 46 H7 result (Spearman -0.97) is circular and gets a note; its verdict is not rewritten. Existing dev/val judge calls stay valid; rule-side results are recomputed. `freeze-devval` runs only after this fix.
2. **H1 metric (replaces Amendment 1 item 7).** Miss rate = planted major or critical errors that V3 does not route / all planted major or critical errors. Pass if the one-sided 95% Clopper-Pearson upper bound is <= 2% and the share of harmless reports routed is <= 30%. Reason: the old denominator depends on how many errors the set contains.
3. **Set C size.** At least 400 planted major or critical errors by field weight, with matched harmless rewordings and LOD items; at least 30 groups per organ or mark "too small to compare".
4. **Additional variants (fixed now).** V5: V1 with differences merged by clinical concept (size = {size_mm, size_pct, size}; head circumference = {hc_mm, hc_abs_mm}), one penalty per concept at the highest severity. V6: V1 without the zero floor, score = 1 / (1 + sum of penalties). V0 to V4 are unchanged. V3 stays primary.
5. **Second judge (descriptive H9).** Run V3 audit prompts with Meta-Llama-3.1-8B-Instruct 4-bit as well as Gemma-2-9B-it. Qwen is not a judge (extractor and Set A writer); Mistral is not a judge (Set C writer). Llama-judge Stage 1 trials use only new Mistral dev data, never Set B. Both judges are reported; if they disagree on H1 or H2, report both and do not pick afterwards. Gemma stays primary.
6. **Two-stage rule.** Stage 1: free trials on dev/val only, every trial logged in `trial_log.csv` (never deleted), stop at 20 trials or 3 calendar days, selection metric fixed as catch rate of major or critical errors at <= 30% harmless routed, on dev, ties broken by fewer model calls. Stage 2: the best 1 to 3 variants go in `frozen_variants.json` with a SHA-256, committed before Set C generation, then run once on Set C alongside V0 to V6. The total Stage 1 trial count is reported. The primary variant stays V3 unless the freeze file names another before Set C exists.
7. **Paper-exact CRQS comparator.** Reading the full paper (arXiv 2607.18448v1) showed that Eq. (6) and Appendix A.7 disagree on signs, and that Eq. (4) counts contradicted fields in HR as well as in CDS. Our Step 46 adaptation differs from Eq. (4) and (5). Step 47 reports both "CRQS-style (Step 46 adaptation)" unchanged and "CRQS paper-exact" (HR per Eq. 4, CDS per Eq. 5 over all common fields, signed weights 0.3/0.4/-0.2/-0.4, divided by 0.7, unclipped and clipped). Both receive the same equal-budget cutoffs rule as Amendment 1 item 5.
8. **Extractor hand check.** Before any Set C score is computed, 50 Set C reports (stratified organ x error/harmless, seed 0) are exported to `handcheck_setC.csv` with extractor v5 fields beside the text, no scores shown. Faviana or Harshal mark each field correct or wrong. Field accuracy with CI is reported per organ. If accuracy is below 90%, all Set C results are labelled "extractor not validated on this text". No variant changes.
9. **Order of operations.** (a) dev/val `calls` finish; (b) code patched for items 1, 4, 5 and 7, unit test passes; (c) this amendment, the patched code and a SHA-256 of both are committed and pushed; (d) `freeze-devval`; (e) Mistral download, Set C plan and generation; (f) hand check; (g) test calls and `score-test` once.
